1adjust_ranking lit global_score — les recettes ont final_score

cycle_engine.adjust_ranking() calcule le score composite avec r.get("global_score", r.get("_adaptive_score", {})) mais les recettes sortant de batch_score portent final_score. Le fallback est toujours 5.0 : le cycle ne déplace jamais le classement.

2Régression _GRAPH_PATH post-migration flat → sous-package

En migrant graph_engine.py vers graph_engine/core.py, __file__.parent.parent résout désormais backend/engine/ au lieu de backend/. Le chemin backend/engine/data/graphs/ingredient_relation_graph.json n'existe pas : le graphe renvoie {} silencieusement.

engine/graph_engine/core.py · ligne ~17 → remplacer par DATA_ROOT / "graphs" / ...

Bug silencieux
3_load_data() dans quality.py sans cache

score_recipe() appelle _load_data() qui recharge 7 fichiers JSON à chaque invocation. Sur un batch de 300 recettes : 2 100 lectures disque par pipeline. Migrer vers _MtimeCache ou @lru_cache comme les autres loaders.

engine/score_engine/quality.py · ligne 36

Bug silencieux
4_load_cycle_data() utilise @lru_cache statique

Même bug que graph_engine avant sa migration (point #4 du précédent audit). @lru_cache ne détecte jamais les modifications de female_cycle_nutrition.json. Migrer vers _MtimeCache pour cohérence avec le reste du projet.

engine/cycle_engine.py · ligne 23

Bug silencieux
5cycle_score() recharge le graphe nutrition à chaque appel

cycle_score() appelle load_json(DATA_ROOT / "graphs" / "recipe_nutrition_graph_v1.json") inline. load_json n'est pas mis en cache : chaque calcul de score cycle relit un fichier de 336 KB depuis le disque.

engine/cycle_engine.py · lignes 92–101 → utiliser un loader _MtimeCache dédié

engine/score_engine/quality.py est le seul fichier Python du projet avec des fins de ligne CRLF (Windows). Git le traite comme entièrement modifié sur Linux/macOS. Ajouter *.py text eol=lf dans .gitattributes et normaliser avec dos2unix.

Trois chargements JSON au niveau module utilisent json.load(open(...)) sans context manager. Si le chargement lève une exception, le file descriptor n'est jamais fermé. Utiliser with open(...) as f ou passer par data_io.load_json.
